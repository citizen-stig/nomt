# NOMT audit, 2026-11-23

Target: `master` at `0224973` (upstream `thrumdev/nomt` at `64bde5f` plus five local commits). Scope: correctness, concurrency, memory safety, durability, proof verification. Production assumptions: Linux, io_uring, O_DIRECT, rollback on, overlays, concurrent sessions, `commit_concurrency > 1`, proofs verified by untrusting parties.

## Verdict

Not ready to hold high-value state. Five distinct defects can silently lose or corrupt committed data or produce a wrong root, and each has a failing test on this branch. Three of them need nothing unusual: a multi-worker commit, a rollback followed by a commit prepared earlier, or a disk write error.

No forged-proof acceptance was found: the proof auditor reported no soundness break in `core/src/proof`, and 30 minutes of fuzzing on `proof_verify` and `proof_decode` found nothing. That is absence of a finding, not a proof of soundness.

## How to read the verdict column

- **CONFIRMED (test)**: a test on this branch asserts the correct behaviour and fails on `master`. I ran every one of them myself after the verifiers did.
- **CONFIRMED (Miri)**: Miri reports undefined behaviour on an existing or added test.
- **TRACE**: the code path was read and holds, but nothing reproduced it. Usually because it needs power loss or an I/O error the repo's tools cannot inject.

Severity: **Critical** = wrong root, or committed data silently lost or corrupted. **High** = undefined behaviour, a deadlock or process abort on valid API use, or state that silently diverges after an error. **Medium** = panic, hang or leak on valid use. **Low** = panic or hang on corrupted on-disk input, hardening gaps.

## What this audit did not cover

- **Power loss.** Torture's crash is `abort()`, which keeps the OS page cache, and trickfs's fsync does nothing. Every fsync-ordering statement here (F17 in particular) rests on reading the code. F4 was reproduced with the in-process panic hook, not a real crash.
- **I/O errors other than EFBIG and EBADF** injected in-process. F10 has no reproduction.
- **An independent root oracle.** `api_surface` compares against `build_trie`, which production also uses.
- **Non-Linux paths** (`nomt/src/io/unix.rs`, macOS).
- **Whether the findings exist upstream** or come from the five local commits. Not checked.

## Method

Three mapping passes produced leads. Seven auditors, one per subsystem, read their area and reported 55 claims after discarding 87 leads themselves. Three verifiers with fresh context received each claim without the auditor's reasoning and tried to refute it; they refuted none, confirmed 48 with a failing test and left 7 as plausible. I then ran all 51 tests myself (48 fail on master; 3 need Miri or `debug-assertions` off and pass in a default run) and re-read the code behind every Critical finding. A zero refutation rate is unusual, so treat Low rows as less scrutinised than the Critical and High ones.

## Running the tests

```
cargo test -p nomt -p nomt-core --no-fail-fast -- audit
CARGO_PROFILE_DEV_DEBUG_ASSERTIONS=false cargo test -p nomt --test audit_unsorted_actuals
MIRIFLAGS="-Zmiri-disable-isolation -Zmiri-tree-borrows" cargo +nightly miri test -p nomt --lib -- beatree::branch::node::test::push_chunk
```

`audit_c1_ht_write_error` sets a process-wide `RLIMIT_FSIZE` and must stay alone in its test binary. The only changes to non-test code on this branch are four `#[cfg(test)] mod` lines.
